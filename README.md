# Часовая мастерская (курсовой проект, C++20 + Qt)

## Структура
```
CMakeLists.txt
src/
  core/        
    include/  
    src/      
  gui/        
    include/
    src/       
    resources/ 
```

## Сборка
```
cmake -S . -B build
cmake --build build
ctest --test-dir build          # консольные проверки ядра
build/workshop_gui              # графический интерфейс (если найден Qt)
```
Нужны компилятор с C++20 (GCC 11+, Clang 14+, MSVC 2022) и CMake 3.21+. Для интерфейса — Qt 6 (или Qt 5.15) Widgets.
В Visual Studio проект открывается как папка с CMakeLists.txt. Запускать нужно `workshop_gui.exe`.

## Вход и роли
**Перед первым запуском этой версии удалите старую папку `data`** (формат файлов изменился).
При первом запуске создаётся администратор: логин `admin`, пароль `admin` (смените его: «Файл → Сменить пароль»).
Окно входа предлагает войти как сотрудник или как гость.

| Роль | Разделы | Что может |
|---|---|---|
| Гость | Заказы, Часы, Детали | только просмотр (без персональных данных клиентов) |
| Мастер | Заказы, Часы, Детали | берёт свободные **лёгкие** заказы (сложность 1–3); меняет статус только **своих** заказов («На диагностике», «В работе», «Готов»); добавляет услуги и детали в заказ; списывает детали; не добавляет и не пополняет детали |
| Ресепшен | все | добавляет и правит клиентов и часы; принимает детали и партии на склад (списывать не может); создаёт заказы; назначает мастера на любой заказ (в том числе сложный); выдаёт готовые заказы («Выдан») |
| Администратор | все | всё, включая удаление, мастеров, учётные записи; единственный, кто может изменить выданный заказ или вернуть статус «Принят» |

Сложным считается заказ, в котором есть услуга сложности 4–5: его мастер сам взять не может, назначает ресепшен.
Выдать заказ может только ресепшен (или администратор) и только если заказ «Готов». У готового и выданного заказа нельзя менять
услуги, детали и мастера; в контекстном меню готового заказа остаётся только смена статуса (выдача), у выданного — только «Создать заказ».
При выдаче сама проставляется «Дата выдачи».

## Где лежат данные
Папка `data` рядом с exe (путь показан в строке состояния, «Файл → Открыть папку с данными»): `clients.txt`, `watches.txt`,
`masters.txt`, `orders.txt`, `parts.txt`, `accounts.txt` и `log.txt` (журнал действий). В `accounts.txt` логины и **хеши** паролей (сами пароли не хранятся;
хеш учебный, не предназначен для реальной защиты). Данные сохраняются при выходе и по Ctrl+S.

## Работа с таблицами
- Щелчок по заголовку столбца сортирует таблицу (сначала по убыванию, следующий щелчок — по возрастанию; стрелка в заголовке).
  Сортировка выполняется собственным алгоритмом слияния.
- Ширину столбцов можно менять мышью. Длинный текст виден целиком в подсказке при наведении, а двойной щелчок по часам или заказу
  открывает полную информацию (в том числе неисправность).
- Поиск по любому столбцу — поле сверху (Ctrl+F). Правая кнопка мыши открывает меню для строки (в заказах оно зависит от столбца).
- Тема оформления (светлая или тёмная): «Файл → Сменить тему» (Ctrl+D), выбор запоминается.

## Горячие клавиши
Ctrl+S сохранить · Ctrl+N добавить в текущем разделе · F2 редактировать · Delete удалить · Ctrl+F поиск ·
Ctrl+1…6 разделы (заказы, клиенты, часы, мастера, детали, журнал) · Ctrl+T сменить статус заказа · F5 обновить ·
Ctrl+D сменить тему · Ctrl+L сменить пользователя · Ctrl+Q выход.
В верхней панели остались только «Файл» и «Сотрудники» (для администратора): все действия с данными выполняются внутри разделов.

## Консольная проверка
`workshop_console` — это набор автоматических проверок ядра, а не режим работы программы. В консоли Windows русский
текст выводится в кодировке UTF-8 (включается автоматически). Запускайте из терминала, чтобы окно не закрылось.

## Основные правила
- Статус заказа можно менять в рамках прав роли (см. таблицу выше); в меню показываются только допустимые переходы.
  Мастер меняет статус, услуги и детали **только своего** заказа; ресепшен выдаёт заказ только из статуса «Готов».
- На одни и те же часы нельзя оформить второй заказ, пока первый не выдан.
- Если принимается деталь, которая уже есть на складе (то же название и категория, регистр не важен), её количество
  пополняется на привезённое, новая позиция не создаётся.
- **Журнал действий** (раздел «Журнал», виден только администратору): время, пользователь, роль, действие и подробности.
  Для деталей записывается количество (приём, списание, добавление в заказ и обратно). Пишутся добавление, изменение и удаление
  клиентов, часов, мастеров, деталей, заказов, смена статусов, назначение мастеров, учётные записи и вход сотрудников.
  Права проверяются в ядре (`Workshop`), поэтому их нельзя обойти через интерфейс.
- Срок заказа считается в рабочих днях от даты приёма; в таблице видно, сколько дней осталось (меняется со временем), просроченные заказы красные.
- Деталь (в том числе элемент питания) списывается со склада сразу при добавлении в заказ и возвращается при удалении из заказа или отмене заказа ниже «Готов».
- Запись, на которую ссылаются другие (клиент с часами или заказами, мастер на заказе и т. п.), удалить нельзя.
- Вводимые данные проверяются: имена только буквами, телефон 7–15 цифр, серийный номер латиницей и цифрами, тип механизма выбирается из списка.
- Услуги берутся из каталога (19 позиций) по типу механизма часов. Цена работы зависит от класса марки (обычная ×1,0, средняя ×1,25, премиум ×1,75); списки марок лежат в `ServiceCatalog.cpp` (`brandInfo`) и их можно править. Элемент питания в услугу не входит: мастер добавляет его в заказ как обычную деталь.
- Телефоны автоматически приводятся к виду «+375 29 824 9433».
- Стоимость услуги: C = B·(1 + 0,2·S) + X, срок: T = S + Y
  (B — цена из каталога с учётом марки; кварц: X = 0, Y = 0; механика: X = 25·R, Y = R; хронограф: X = 40·N, Y = N).
